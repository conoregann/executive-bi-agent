# Project documentation

Documentation records durable business language, safety boundaries, and public
behavior. It is not a required reading sequence or a prerequisite for every
implementation. Read only the contract that governs the change; update it only
when that durable behavior changes.

- [Project brief](../Brief.md) — scope and delivery sequence.
- [Discovery](discovery/) — fictional company context and question behavior.
- [Metrics](metrics/) — canonical metric definitions and query boundary.
- [Architecture](architecture/) — evidence and investigation boundaries.

Evaluation cases in `evals/` are required for user-visible or safety-critical
behavior, not routine implementation details.
